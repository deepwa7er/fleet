01 the six rules

The Six Rules

Everything after these is either a consequence of a rule or an extension of one, and every extension names the rule it derives from. That naming discipline is what keeps separate apps looking like one hand made them.

  1. Whitespace separates content. No borders or dividers between items, sections, or text. Proximity and typography carry the hierarchy.
  2. Depth marks interactivity. Solid offset shadows and outlines appear only on things you can press (buttons) or type into (fields).
  3. Warm light mode (cream paper, warm ink); charcoal dark mode. Never pure neutral gray, never brown.
  4. One accent color — a deep Bavarian blue — used only for interactive elements.
  5. Metadata is instrumentation: uppercase, letterspaced, tabular numerals. Dashboard readouts, not prose.
  6. Motion is engineered: short durations, strong ease-out, like a well-damped switch.
02 color · rules 3 & 4

Color

Light mode is warm all the way through. Dark mode is not the warm palette inverted: it is cool charcoal with a blue undertone, so the backlight blue reads as backlight. The chips below render from the live tokens — flip the theme to see both faces.

--bgpaper
--fillsurface
--textink
--text-mutedmeta
--accentinteraction only
--dangera fact, not a mood
--gooda wash, not a signal
--inkkeys and hard shadows

--accent is reserved for interaction: links, primary buttons, focus rings, hover states. A chart line, a heading, or a highlighted figure never gets it — if it's blue, you can click it. --ink is not --text: it means "the hard edge of a physical key" and goes black in dark mode while text goes paper-white. --fill is the only permitted background change — it is how a surface becomes distinct without a border.

03 typography · rule 5

Typography

Three voices, and only three.

Prose

system-ui, sans-serif at 1rem / 1.6. Body text, findings, descriptions. No uppercase, no letterspacing. This paragraph is prose.

Headings

ui-serif, Georgia, serif — the serif is what makes the page a document instead of an app chrome. Tighten tracking as size grows; large type at default tracking always looks loose. This is the h1 scale, set live:

A document, not a dashboard

Instrumentation (rule 5)

The readout voice. One recipe, applied identically everywhere:

font-size: 0.7rem;
font-weight: 600;
letter-spacing: 0.08em;
text-transform: uppercase;
font-variant-numeric: tabular-nums;
color: var(--text-muted);

It marks column headers, timestamps, units, axis labels, key terms, and settings labels — never prose. If a human wrote the sentence for another human to read, it stays lowercase and unletterspaced even beside readouts. This whole page's section numbers and doc block are live examples.

Monospace

ui-monospace, SFMono-Regular, Menlo, monospace — for program output, diffs, and inline literals only. Monospace means "a machine produced this and its alignment carries meaning." Tabular numerals are mandatory anywhere numbers stack.

04 layout · rule 1

Layout & Measure

.container { max-width: 64rem; margin: 0 auto; padding: 1.5rem 1.25rem; }
.measure   { max-width: 40rem; }

40rem is the prose measure — the right measure for reading. Widen the container only for data that genuinely does not fit, and say why in a comment. The page never scrolls sideways; anything wide scrolls inside its own box. Structure comes from vertical rhythm, not rules — the gap between two items is the divider: 

.run        { padding: 0.75rem 0; }
.run + .run { margin-top: 1rem; }   /* the gap replaces the divider */
05 depth · rule 2

Depth — the only place it appears

The button is a physical key: accent keycap, 2px ink edge, solid offset shadow. The press slides it down into its own shadow — the offset and the translate must match or the key doesn't land. The field is a recess: no border at all, the fill surface and radius do the work, and focus draws the only outline on the page. Nothing else may borrow either treatment. Try the keys below.

Variants recolor, never restyle — the border, radius, and shadow are constant, and that constancy is what says "pressable". radius: 10px is the system's one geometry constant.

06 motion · rule 6

Motion

0.15s cubic-bezier(0.2, 0.8, 0.2, 1) — damped, not springy. That is the whole vocabulary. Motion exists to make the key press feel mechanical; it never reveals content, never gates a click, never loops. Honor the user's setting: 

@media (prefers-reduced-motion: reduce) {
    * { transition: none !important; }
}
07 components · rules 1 & 5

Components

Lists (rule 1)

No markers, no borders — the gaps carry the grouping. The title is text at rest, accent on hover:

  • Reading the run — 21.1 km, delivered on time
  • Threshold check — effort within target band
  • Shoes — 612 km logged, 188 remaining

Tables (extension of rules 1 & 5)

No rules, no zebra striping. Every header is instrumentation; every figure is tabular. Units live in the header, numbers right-aligned, the label column left and 600.

The verdict (extension of rule 1)

A conclusion the reader must not miss — separated by space and a shift to serif, not by a box or a background:

On 21.1 km at 5:32 pace, effort ran 7/10 — comfortably within the target band.

The reading key (extension of rules 1 & 5)

Rows are separated by space, never rules. The band the run landed in is promoted by weight and color — never by a colored box:

60–89%

Log / program output (extension of rule 1)

Monospace on a fill surface, capped height, scrolls inside itself:

08 extending · the method

Adding to the System

Extensions are made one way, and the price of admission is naming the rule:

  1. Name the rule you are extending. "Extension of rule 1" is the price of admission.
  2. Say what the existing system lacked. The notes app had no "good" color until a signed gap needed one; it was added muted, so it stays a wash behind data.
  3. When a rule genuinely strains, resolve it — do not except it. A transcript across four hundred events gets rhythm from rule 5, not a line drawn anywhere; a diff gets its extra signal by coloring line role, reusing the status colors.
  4. Never reach for a border. If two things need separating, they need more space or a different type treatment.
09 gothic · extensions pending

Gothic Inspiration

Rev A tried eleven Gothic ideas here and kept five. What survived is not ornament: Gothic's translatable DNA for this system is verticality, structure, and one sacred thing per page. The kept ideas are now part of DW-001 (§11 of the guide); the rejected ones are recorded here with their reasons so nobody re-tries them. This page is the reference implementation for G1, G2, G5, and G11 — deepwater-404.html is the specimen for G10.

  1. G1 · The nave is whitespace

    extends rule 1 kept — part of DW-001 §11

    Cathedrals are full of emptiness — the vertical void is the architecture. Deeper rule 1: taller line-height on headings, more air above h1/h2, the masthead treated like the vault. Cheapest and most structural idea; barely changes the look. Applied here: masthead padding grows to 6rem, heading line-height to 1.4, section gaps to 6rem, prose gaps to 1.25rem.

  2. G2 · Nave and aisle layout

    extends rules 1 & 5 kept — part of DW-001 §11

    Make the two-column page officially nave + aisle: prose in the nave, instrumentation and metadata in the aisle. Gothic facades are organized in registers/bays; the metadata rail becomes the aisle. Applied here: every section is a bay — its number and the rule it derives from sit in the aisle rail; prose and components fill the nave.

  3. G3 · The vault of the document

    meta / structural rejected — pure metaphor, no behavior

    Frame the guide itself as a vault: the six rules are six ribs meeting at a keystone — the keystone being the naming discipline (§8). Purely textual; gives the composite guide a Gothic structure.

  4. G4 · The pointed arch is the altar

    extends rule 1 rejected — a second geometry strained the depth rule

    A lancet — pointed-arch top — as the one geometric signature, reserved for the verdict block (§7): already "a conclusion the reader must not miss", it becomes the only pointed shape on the page. Everything else keeps the 10px radius.

  5. G5 · The illuminated initial

    extends rule 1 kept — part of DW-001 §11

    One drop-cap per page opening the title or first section — the incipit, the manuscript letter. Ink or muted wash, never accent (rule 4: if it's blue you can click it). The guide's "one ornament" becomes this. Applied here: the masthead title opens with an illuminated "D" on a fill panel — the page's one ornament.

  6. G6 · The quatrefoil replaces the divider

    extends rule 1 rejected — clutter; the pure void is stronger

    Section breaks are currently pure space. A tiny quarterfoil/tracery glyph centered between major sections would be the only permitted glyph ornament — ornament as the gap, not a border.

  7. G7 · Chartres blue — the light in the dark

    deepens rules 3 & 4 rejected — framing changed nothing; stone broke one-surface

    Bavarian blue is, coincidentally, the blue of Chartres stained glass. Reframe the accent as "the light in the dark": dark mode is the nave, light mode the day-lit cathedral. Documentary only — no code change. Optionally add a warm-limestone --stone surface.

  8. G8 · Stone grain

    rejected — the flat-paper rule

    A near-invisible texture (2–3% opacity tracery) on the page background, reading as stone or paper grain. Survives only if it stays under the threshold of "surface". Most tension with the flat-paper rule.

  9. G9 · Rubrication

    rejected — rule 4: color means something

    Medieval red for key lines in the masthead, like a manuscript rubric. Violates "accent is interaction" — the danger red exists to mean something. Only defensible restricted to the document header block.

  10. G10 · The gargoyle

    extends rule 1 kept — part of DW-001 §11

    One allowed moment of playfulness — the 404 page is a gargoyle. Gothic cathedrals had grotesques; comedy needs a straight man. Applied here: a live 404 page, DW-404 — Nothing here but a gargoyle, where the stone grotesque is the page's one ornament and the rest stays strictly in system.

  11. G11 · Blackletter masthead

    new display voice kept — part of DW-001 §11

    A Fraktur display voice for the app/run title only — never body or headings (Georgia stays). Fraktur is nearly unreadable at length, so the discipline is self-enforcing. Applied here: the masthead title is set in UnifrakturCook, the illuminated initial keeping it company; every other heading stays Georgia. Falls back to serif if the font can't load.

Motion, deliberately unchanged. Rule 6 forbids content-revealing motion, so Gothic "solemnity" (slower reveals) contradicts it. The damped 0.15s press is already mechanical — the feel of a heavy cathedral door. No motion candidate is proposed.
