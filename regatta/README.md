# regatta

Sequence-voting party game. Anyone proposes a **course** — a titled gauntlet
of steps whose quantities **add up to exactly ten** ("3 donuts eaten" +
"2 shots" + "2 miles run" + … = 10), each step an activity from the catalog —
and the crew votes. Ten whole units is the whole budget, so a push-up costs as
much as a donut: spending it well is the game. The board ranks courses by
votes; ties keep the earlier proposal ahead.

One binary serves the JSON API and the built web view over one SQLite store
(fleet-common scaffolding: `/healthz`, the `{"error"}` contract, SPA fallback,
migrations).

## The rules

- A proposal is any number of steps whose quantities — whole numbers from 1 to
  10 — add up to exactly ten (`COURSE_TOTAL` in `core/model.rs`).
- Voting is set membership: one vote per name per proposal, cast and retract
  are idempotent, so the tally can't be inflated by double-clicks.
- The catalog is fully user-editable from the UI: categories (seeded with
  Foods, Misc, Physical, Video games, Games & puzzles, Social, Exploration,
  Chance, Adulting, Creative) and activities alike. Keep activities easily
  quantifiable — counts, streaks, minutes, miles — so no judging panel is
  needed. An activity can't be deleted while a proposal references it, nor a
  category while it still has activities.
- Voter identity is an honor-system name kept in the browser — the game runs
  on the tailnet for friends, not the open internet.

## Run it

```
cargo run -p regatta            # http://127.0.0.1:8096
cd web && bun install && bun run dev   # Vite dev server proxying /api
```

`REGATTA_DB`, `REGATTA_ADDR`, `REGATTA_WEB_DIR` override the defaults
(XDG data dir, `127.0.0.1:8096`, `web/dist`).

## Deploy

`tugboat deploy` from this directory (see `deploy.toml`); one-time infra is
`deploy/provision.sh`. Breakwater fronts it at
`https://regatta.intern.deepwa7er.net`; the route and the fleet-backup entry
are generated by `tugboat fleet gen`.
