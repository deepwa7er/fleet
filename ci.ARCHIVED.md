# CI — archived 2026-08-13

The GitHub Actions workflow is archived. There is no automated gate on
`origin/main`; `tugboat` still ships it.

- **Why:** the design was not well thought out and is not wanted in its current
  form — per 2026-08-13 decision. To be replaced by a better solution later. It
  was also failing: the `web` job had been red since drydock was archived
  (`853c7c6` deleted `drydock/`, `ci.yml:35` still built it), so `main` failed
  for reasons unrelated to code health and the four surviving web apps were
  never built anyway. See card https://fizzy.intern.deepwa7er.net/1/cards/46
  (supersedes https://fizzy.intern.deepwa7er.net/1/cards/45, which proposed
  repairing the `web` job).
- **Resurrection pointer:**
  - Git tag: `archive/ci-2026-08-13` (annotated, pushed to origin)
  - Branch: `archive/ci` (points at the same commit as the tag, pushed)
  - To resurrect: `git checkout archive/ci -- .github/`
  - Then fix `ci.yml`'s `web` job before trusting it — the app list is
    hardcoded and already stale (see "If you rebuild this" below)
- **What was removed in this commit:** `.github/workflows/ci.yml` (the only
  workflow; the now-empty `.github/` goes with it), and every reference to CI in
  `README.md`, `.agents/skills/fleet/SKILL.md`, `rust-toolchain.toml`,
  `tugboat/src/gen.rs`, `tugboat/src/main.rs`, and the generated header in
  `breakwater/breakwater.toml`.

History is intact — no code lost.

## What is no longer enforced

The three jobs were the only automated enforcement of:

| # | Check | Status now |
|---|-------|-----------|
| 1 | `cargo test --workspace` | local gate, `.agents/skills/fleet/SKILL.md` §3 |
| 2 | `cargo clippy --workspace --all-targets -- -D warnings` | local gate, §3 |
| 3 | `tugboat fleet gen --check` | local gate, §3 — **added in this commit** |
| 4 | every web app's `bun run build` (includes tsc typecheck) | unenforced |
| 5 | tidepool `go vet` / `go test` / `go build` | unenforced |

**#3 is the one with teeth.** `breakwater/breakwater.toml` and
`fleet-backup/state.sh` are generated by `tugboat fleet gen` from each service's
`deploy.toml`. Nothing else verified they still matched their declarations, so
without it a route or backup entry can drift silently and only surface at deploy
time. It is now part of the pre-PR gates in the fleet skill, which is why that
list gained a fourth command.

#4 and #5 have no replacement. A web app's TypeScript can break, or tidepool can
stop compiling, without anything noticing until someone builds it by hand.

## If you rebuild this

Two lessons from what was archived, both learned the hard way:

1. **Discover, don't hardcode.** The `web` job listed its apps literally
   (`for app in drydock clothes lighthouse regatta source`), so archiving one
   service broke the job for all of them. This repo's own convention is
   discovery — `fleet.toml`: "deployability is discovered, not declared…
   nothing to register when adding a service." Iterate the directories that
   actually contain `web/package.json`.
2. **A red gate that is red for an unrelated reason is worse than no gate.**
   The `web` job failed on its first iteration for months of commits, which made
   a genuine failure indistinguishable from the known one. Whatever replaces
   this should fail loudly and specifically, or not exist.
